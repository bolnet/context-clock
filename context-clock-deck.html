Measuring context rot — how a long session forgets, and why every model forgets the same way

7 models benchmarked 74 tests passing ~$0.27 total cost
01
the setup

One long session. No compaction.
Plant a needle, then probe for it every turn.

①
Run a session that never compacts — the transcript just keeps growing.
②
Plant a needle early: a 6-char code like k44cb6 buried in a memo.
③
Each turn, probe for the planted code and grade by exact match — no LLM judge.
④
The needle is random per memo, so recall can’t be faked by pattern-inference.

As the transcript outgrows the context budget, the oldest tokens fall away and the planted code becomes unrecallable. That collapse is context rot — and context-clock measures it per turn.

02
the core measurement

Recall decays in a clean staircase

t1turn 100%recall 0cum tokens
recall % (oldest needle)context fill toward window
  • Recall holds at 100% while the needle still fits in context.
  • Then it collapses 100→67→33→0 over three turns as the window overflows.
  • Rot onset is turn 12; recall hits zero at turn 14 and stays there.
  • The oldest tokens are dropped — the model literally no longer has the needle.
03
why you can trust it

A predictable needle can be faked — ours can’t

deterministic needle — faked to t27unpredictable needle — drops t16
  • With a deterministic needle, a 14B model “held on” all the way to turn 27 — even recovering to 100%.
  • But those memos were long gone from context. It was inferring the pattern, not recalling the code.
  • Switch to a random, unpredictable needle and the curve drops at turn 16 — real retention only.
  • This is why context-clock’s recall numbers are credible.

3B → 671B · one staircase

All 7 models trace the identical 100→67→33→0 decay. They differ only in onset: the four local num_ctx runs (3B–24B) rot at turn 14; the three client-windowed runs — DeepSeek-R1, GPT-5.4-mini, Claude Haiku — rot earlier at turn 10. A bigger or smarter model doesn’t escape it — onset just tracks the context budget.

08
what to take away

Four findings

01

Rot is model-independent

With no compaction, all 7 models (3B→671B) rot on the identical 100→67→33→0 staircase. Only the onset turn differs.

02

Onset tracks context budget

Local num_ctx runs rot at turn 14; tighter client-windowed runs at turn 10. More budget delays the cliff — it never removes it.

03

The benchmark resists faking

A random needle blocks pattern-inference — a deterministic one let a 14B model fake recall to turn 27. Unpredictability is what makes recall numbers real.

04

External memory is the lever

Retrieve-what’s-needed stays flat (3,060 vs 23,449 tokens), zero compactions, perfect recall. A bigger window is not the fix.
