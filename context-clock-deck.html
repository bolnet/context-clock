Measuring context rot in long LLM sessions — and what actually fixes it

57 tests green 3 models benchmarked $0 API cost
01
the question

A session runs long. The context window is finite.
What breaks — and does a bigger/better model save you?

①
Context fills toward the window limit
②
Recall of old facts decays
③
Tokens exhaust — cost climbs
④
The agent is forced to compact

context-clock drives all four on purpose, on a local model, and measures them per turn.

02
how it works

The benchmark loop

inject
Each turn adds a sizeable NIAH document — a varied haystack with one needle: "the vault code is k44cb6"
probe
Every turn, ask for the oldest codes. Grade by exact match — no LLM judge.
measure
Record recall, live context, tokens used & cumulative — per turn.
  • The needle is deterministic per memo but unpredictable (k44cb6, not k007) — so a model must recall it, not infer it.
  • No external memory, no compaction in the core run — the model is on its own.
03
the core measurement

Rot until complete — no intervention

recall % (oldest facts)live context tokens
  • Recall holds at 100% while everything fits…
  • then collapses 100→67→33→0 over three turns as the window overflows.
  • The run self-terminates at turn 16 on sustained zero.
  • Ollama truncates the oldest tokens — the model literally loses them.
04
credibility check

A "smarter" model looked robust — it was cheating

qwen2.5:14b — guessable needleqwen2.5:14b — unpredictable needle
  • With a guessable needle (Memo N→k00N), the 14B model "held on" to turn 27 — even recovering to 100%.
  • But by turn 16 those memos are gone from context. It was inferring the pattern, not recalling.
  • Fix: unpredictable codes → the curve drops at turn 16. Real retention only.
05
the headline

Raw context rot is model‑independent

all 4 models rot at turn 16

Across an 8× parameter spread (3B→24B) and three families, every model traces the identical 100→67→33→0 curve. Truncation drops the oldest tokens regardless of model size — a bigger model doesn't help.

Token consumption scales super-linearly with window size — ~6× the tokens from 1024→4096.

Yet every window decays to the same recall floor. More room buys time, not reliability — at far higher cost.

08
what to take away

Four findings

01

Rot is model-independent

At a fixed window with no intervention, 3B and 14B models rot identically — truncation doesn't care how smart the model is.

02

Bigger window ≠ fix

It delays the cliff but never escapes it, and burns super-linearly more tokens to get there.

03

Compaction trades detail for room

An agent intervention — raw models truncate, they don't summarize. Model size matters here, not for raw rot.

04

External memory is the lever

Retrieve-what's-needed stays flat, cheap, and never forgets.
